## Цель работы

Освоение базовых навыков настройки рабочего окружения Java-разработчика, получение практического опыта работы с системой контроля версий Git. Изучение основ объектно-ориентированной парадигмы: создание классов, применение модификаторов доступа (`private`, `public`), реализация инкапсуляции через методы-аксессоры (геттеры и сеттеры с валидацией) и создание экземпляров классов.


## Структура проекта

Весь исходный код располагается в директории `src/`:

* `Book.java` — реализация базового задания на паре. Класс описывает сущность "Книга". Включает проверки на корректность ввода текстовых данных (название и автор не могут быть пустыми) и логическую проверку года издания (не больше текущего года).
* `Product.java` — реализация индивидуального задания (Вариант 3). Класс описывает сущность "Товар". Реализована строгая валидация числовых полей: цена строго больше нуля, остаток на складе не может быть отрицательным. Форматирование цены реализовано через `String.format` (два знака после запятой).
* `Main.java` — точка входа в приложение (`public static void main`). Содержит создание объектов классов `Book` и `Product`, их инициализацию тестовыми данными и вывод результатов в консоль.

## Контрольные вопросы
**1. Что такое класс и объект? В чём их различие?**

* **Класс** — это шаблон, чертёж или описание, которое определяет структуру (поля) и поведение (методы) будущей сущности.
* **Объект (экземпляр класса)** — это конкретная реализация этого чертежа в оперативной памяти программы, обладающая собственным уникальным состоянием.
* **Различие:** Класс — это абстракция (понятие «Автомобиль» в целом), а объект — это конкретная вещь (твоя машина с конкретным VIN-номером и цветом).

**2. Какие модификаторы доступа существуют в Java?**

* `private` — доступ разрешен только внутри того же самого класса.
* *Default (package-private)* — (когда модификатор не указан) доступ разрешен классам внутри того же пакета.
* `protected` — доступ разрешен внутри пакета, а также во всех классах-наследниках (даже в других пакетах).
* `public` — доступ разрешен из любого места программы.

**3. Что такое инкапсуляция? Зачем она нужна?**
**Инкапсуляция** — это принцип ООП, заключающийся в объединении данных и методов для работы с ними внутри одного класса, а также скрытии деталей внутренней реализации от внешнего мира.
Она нужна для:

* Защиты данных от некорректных изменений (через валидацию в сеттерах).
* Упрощения поддержки кода (можно менять внутреннюю логику класса, не ломая остальную программу).
* Контроля доступа к информации (например, можно сделать поле только для чтения, убрав сеттер).

**4. Чем конструктор отличается от обычного метода?**

* **Имя:** Конструктор всегда должен называться точно так же, как и сам класс (с большой буквы).
* **Возвращаемый тип:** Конструктор не имеет возвращаемого типа вообще (даже `void`), тогда как у метода он должен быть обязательно.
* **Вызов:** Конструктор вызывается только один раз в момент создания объекта (через оператор `new`), а обычные методы можно вызывать у готового объекта сколько угодно раз.

**5. Для чего используется ключевое слово `this`?**
Ключевое слово `this` хранит ссылку на текущий экземпляр объекта. Чаще всего оно используется:

* Для разрешения конфликта имен, когда параметры метода совпадают с названиями полей класса (например, `this.price = price;`).
* Для вызова другого конструктора этого же класса (например, `this(id, name);`).
* Для передачи самого себя в качестве параметра в другие методы.

**6. Что такое классы-обёртки? Что такое автоупаковка?**

* **Классы-обёртки (Wrapper classes)** — это специальные классы, которые инкапсулируют в себе значения примитивных типов данных (например, `int` -> `Integer`, `double` -> `Double`). Они нужны там, где Java требует использования именно объектов, а не примитивов (например, в коллекциях `ArrayList`).
* **Автоупаковка (Autoboxing)** — это автоматическое преобразование компилятором Java примитивного типа в соответствующий класс-обёртку (например, когда ты пишешь `Integer num = 5;`, под капотом происходит `Integer num = Integer.valueOf(5);`).

**7. Почему прямой доступ к полям класса считается плохой практикой?**
Если сделать поля `public` и обращаться к ним напрямую (`product.price = -100;`), невозможно проконтролировать корректность записываемых данных. Это нарушает инкапсуляцию, позволяет перевести объект в невалидное состояние и создает жесткую зависимость внешнего кода от внутреннего устройства класса, что сильно усложняет дальнейшее развитие программы.

**8. Какие преимущества даёт ООП по сравнению с процедурным программированием?**

* **Моделирование:** Программа строится вокруг понятных объектов реального мира, а не вокруг абстрактных функций.
* **Переиспользование кода:** Благодаря наследованию и композиции можно не писать один и тот же код дважды.
* **Безопасность:** Инкапсуляция защищает данные от случайной порчи.
* **Масштабируемость:** Крупные проекты на ООП гораздо легче поддерживать, расширять и распределять между разработчиками в команде.
